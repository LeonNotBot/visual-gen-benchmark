## 文生图提示词写作规范（Qwen-Image）

来源标记见 SKILL.md：[2512] [v1] [API] [补充]。官方原文在 `official/`。

### 1. 先归类：人像 / 含文字图 / 通用图

| 类型 | 判定 | 来源 |
|---|---|---|
| 人像 | 画面以人物为核心主体。提示词只写了“人像”“头像”而没说是谁时，也按人像写，并补出具体人物 | [2512]（后半句只在英文版） |
| 含文字图 | 画面包含可识别文字，如海报、招牌、信息图、PPT、漫画 | [2512] |
| 通用图 | 不含人物主体或文字，以景物、静物、抽象构成为主 | [2512] |

同时有人物和文字时，按含文字图写，人物外观仍要写清。官方没有写优先级，这里依据官方含文字图示例（如电影海报示例里也描述了人物）。[补充]

### 2. 最终提示词的形式

- **一段连贯的描述性文字**，不用列表、编号、标题。[2512]
- 信息图、图表类可以用换行分区，区内可用“-”引出条目，但条目仍写成描述句。[2512]（只在英文版）
- **语言跟随输入**：输入里有汉字就写中文，否则写英文。[2512]（代码 `get_caption_language`）
- **长度**：
  - 人像：中文 150 字以内 [2512 中文版]；英文约 200 词 [2512 英文版]。其他类型官方没有字数要求。
  - API 上限：qwen-image-2.0 系列正向提示词 1300 Token，其他模型 800 Token，超出自动截断。[API]
- **质量后缀**：早期版改写工具在结果末尾固定追加“超清，4K，电影级构图”（英文 “, Ultra HD, 4K, cinematic composition.”）[v1]；2512 版代码里定义了这个后缀但没有追加。做对比测试时，同一批要么都加、要么都不加。[补充]

### 3. 通用要求（所有类型）

1. **补细节的分寸** [2512]
   - 原描述不够：补符合逻辑的环境、光影、质感、氛围。
   - 原描述够了：只做必要修改。
   - 原描述冗余：保留原意，精简。
   - 补充内容要和已有信息风格统一、逻辑自洽；**原有内容和概念不得修改**；简单场景保持克制。
2. **专有名词原样保留**：人名、品牌、地名、IP、影视游戏名、标语原文、网址、电话。[2512]
3. **文字**
   - 画面里的文字放进引号：中文提示词用中文双引号“ ”，英文提示词用英文双引号 " "。[2512]
   - 写清内容、位置、横排 / 竖排 / 换行、字体风格、颜色、大小、呈现方式（印刷、刺绣、霓虹灯等）。[2512]
   - 提示词暗示有文字时，补成具体内容，不写“名单”“列表”这类模糊说法，补充内容不要过长。[2512] 例：输入“邀请函上写着名字和日期等信息”，改为：邀请函的下方写着“姓名：张三，日期： 2025年7月”。[v1]
   - 画面没有文字时，写明“图像中未出现任何可识别文字”（英文 “The image contains no recognizable text.”）。[2512]
   - 用户没要求的文字一律不加。[v1][2512]
4. **明确整体艺术风格**，如写实摄影、动漫插画、电影海报、赛博朋克概念图、水彩手绘、3D 渲染、游戏 CG。[2512] 用户没指定时选最合适的：古诗 → 中国水墨或水彩；真实照片 → 纪实摄影或真实摄影。[v1]
5. **古诗词**：强调中国古典元素，避免西方、现代、外国场景。[v1]
6. **逻辑关系**（食物链、流程）要保留，用箭头等看得见的方式表达。例：“画一个草原上的食物链” → 改写后要有箭头表示食物链关系。[v1]
7. **正向提示词里不写否定词**。例：“不要有筷子” → 改写后不出现筷子。[v1] 需要排除的内容写进 `negative_prompt`。[API]
### 4. 按类型写的要素

#### 4.1 人像 [2512]

按这个顺序写（英文版说顺序是推荐，可以为了行文自然调整；中文版要求按此顺序）：

1. **身份**：种族、性别、具体年龄或较窄的年龄段（如“约25-30岁”），不用“年轻”“年老”这类含糊词（“具体年龄段”和本句只在英文版）。
2. **服装、发型、配饰**：上衣、下装、鞋、外套的类型和面料质感；发色、长度、发型；头饰、耳环、项链、戒指、眼镜。
3. **脸部和皮肤**：脸型、五官特征、表情、肤色、肤质、妆容。
4. **姿态和动作**：身体姿势、手势、视线方向、头部角度、与道具的互动。姿态要符合人体结构和物理常识（英文版）。
5. **背景与环境**：具体场景、背景物体、光照（方向、强度、色温）、天气、整体氛围。
6. **其他物体**：数量、颜色、材质、位置，以及和人物的空间或功能关系。

篇幅：中文 150 字以内，英文约 200 词。

#### 4.2 含文字图 [2512]

1. **忠实还原文字**：写明文字在哪（招牌、屏幕、衣物、包装、海报）；准确转录全部文字，含标点、大小写、换行、排版方向；写字体风格、颜色、大小、清晰度、有无描边 / 阴影；非中文文字保留原文并注明语种。
2. **文字与载体的关系**：呈现方式（印刷、LED 屏、霓虹灯、刺绣、涂鸦）；构图作用（标题、标语、品牌标识、装饰）；和人物或物体的空间关系（手持、张贴、投影）。
3. **环境与氛围**：场景类型；光照对文字可读性的影响（反光、背光、夜间照明）；整体色调和艺术风格。
4. **信息图 / 知识类**：文字不完整但暗示有文字时，补布局和精确、精简的典型文案；用户已给详细文字时以忠实保留为主，只做必要润色；文字必须和画面内容一一对应。

#### 4.3 通用图 [2512]

1. **核心视觉元素**：主体的种类、数量、形态、颜色、材质、状态（静止 / 运动）、细节特征；前景 / 中景 / 背景的层次和物体间相对位置、距离；光源方向、明暗对比、主色调、高光 / 反光 / 阴影；表面质感（光滑、粗糙、金属、织物、透明、磨砂）。
2. **场景与氛围**：场所类型；时间与天气（清晨薄雾、正午烈日、雨后湿润、雪夜、黄昏暖光）；情绪基调。
3. **多物体关系**：功能关联（茶壶与茶杯）；动作互动（风吹窗帘）；比例与尺度（高楼与行人、微观特写）。

### 5. 官方示例（原文摘录）

**2512 版，人像**（中文版示例输出，原文无对应输入）：

**早期版，输入 → 改写**（示范“模糊文字补成具体内容”和“逻辑关系用箭头”）：

- 输入：一张红金请柬设计，上面是霸王龙图案和如意云等传统中国元素，白色背景。顶部用黑色文字写着“Invitation”，底部写着日期、地点和邀请人。
- 改写：中国风红金请柬设计，以霸王龙图案和如意云等传统中国元素为主装饰。背景为纯白色，顶部用黑色宋体字写着“Invitation”，底部则用同样的字体风格写有具体的日期、地点和邀请人信息：“日期：2023年10月1日，地点：北京故宫博物院，邀请人：李华”。霸王龙图案生动而威武，如意云环绕在其周围，象征吉祥如意。整体设计融合了现代与传统的美感，色彩对比鲜明，线条流畅且富有细节。画面中还点缀着一些精致的中国传统纹样，如莲花、祥云等，进一步增强了其文化底蕴。

- 输入：手绘小抄，水循环示意图
- 改写：手绘风格的水循环示意图，整体画面呈现出一幅生动形象的水循环过程图解。画面中央是一片起伏的山脉和山谷，山谷中流淌着一条清澈的河流，河流最终汇入一片广阔的海洋。山体和陆地上绘制有绿色植被。画面下方为地下水层，用蓝色渐变色块表现，与地表水形成层次分明的空间关系。 太阳位于画面右上角，促使地表水蒸发，用上升的曲线箭头表示蒸发过程。云朵漂浮在空中，由白色棉絮状绘制而成，部分云层厚重，表示水汽凝结成雨，用向下箭头连接表示降雨过程。雨水以蓝色线条和点状符号表示，从云中落下，补充河流与地下水。 整幅图以卡通手绘风格呈现，线条柔和，色彩明亮，标注清晰。背景为浅黄色纸张质感，带有轻微的手绘纹理。

### 6. 调用参数

| 参数 | 写法 | 来源 |
|---|---|---|
| `prompt` | 按本规范写；qwen-image-2.0 系列上限 1300 Token，其他 800 Token，超出自动截断 | [API] |
| `negative_prompt` | 写不希望出现的内容，不超过 500 字符，超出自动截断。官方示例：“低分辨率，低画质，肢体畸形，手指畸形，画面过饱和，蜡像感，人脸无细节，过度光滑，画面具有 AI 感。构图混乱。文字模糊，扭曲。” | [API] |
| `prompt_extend` | 默认开启，只改写正向提示词。想要模型补细节、内容更多样就开；想让细节可控就关 | [API] |
| `size` | 2.0 系列总像素 512×512 至 2048×2048，推荐 2688*1536（16:9）、1536*2688（9:16）、2048*2048（1:1，默认）、2368*1728（4:3）、1728*2368（3:4） | [API] |
| `seed` | 固定 seed 结果相对稳定，但不保证完全一致 | [API] |

- 已经按本规范写好的提示词，建议关掉 `prompt_extend`，否则会被再改写一次，实际用的提示词和你写的不一样。[补充，依据 API 文档“细节可控建议关闭”]
- 本地开源部署（如 ComfyUI）没有 `prompt_extend`，提示词要自己按本规范写好；开源 README 在不用反向提示词时建议传一个空格 `" "`。[补充；空格写法见开源 README]
- 做对比测试时，记录 `prompt_extend` 开关和实际提示词，同一组对比保持一致。[补充]

### 7. 交付前自检

- [ ] 一段连贯描述，没有列表、编号、标题（信息图类的分区除外）
- [ ] 已归类为人像 / 含文字图 / 通用图，并覆盖该类要素
- [ ] 写明了整体艺术风格
- [ ] 专有名词、用户给定的文字一字未改
- [ ] 每段画面文字都在引号里，写了位置、字体、颜色、大小、呈现方式；没有“列表”“名单”这类模糊文字
- [ ] 用户没要求文字时，没有添加文字
- [ ] 正向提示词里没有否定词，排除项已放进 `negative_prompt`
- [ ] 没有改变用户原意，没有加入和原意冲突的元素
- [ ] 长度在上限内（人像中文 150 字 / 英文约 200 词；API 1300 / 800 Token）
- [ ] 已确定 `prompt_extend` 开关
